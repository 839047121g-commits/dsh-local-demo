# dsh-local-demo

DSH Superagent 登录失败提示修复实验。这个仓库用于观察从 GitHub 请求、接单、代码修改到 PR 评审反馈的过程。

## 运行

需要 Node.js 20 或以上版本。没有第三方依赖，不需要安装依赖、启动数据库或配置环境变量。

```bash
npm test
```

## 实验基线

`src/login-message.js` 导出 `getLoginFailureMessage(errorCode)`，将登录接口错误码转换为提示文案。当前实现对所有输入返回“登录失败”，测试记录这个初始行为。

| 错误码 | 场景 | 当前提示 |
| --- | --- | --- |
| `PASSWORD_INVALID` | 账号或密码错误 | 登录失败 |
| `SERVICE_UNAVAILABLE` | 服务暂不可用 | 登录失败 |
| `NETWORK_TIMEOUT` | 网络连接超时 | 登录失败 |
| 未知、空或缺失错误码 | 无法确定原因 | 登录失败 |

这里只模拟提示转换，不包含真实认证、网络请求或页面。后续改动应保持函数接口不变，并更新测试以验证新的验收要求。

## 第一轮：修复与交付

基线提交并推送后，用请求者账号新建 GitHub Issue：

> @pressure001 请改善登录失败提示：PASSWORD_INVALID 提示“请检查账号或密码”，SERVICE_UNAVAILABLE 提示“服务暂不可用，请稍后再试”，其他错误码及空或缺失错误码保留“登录失败”。仅修改提示映射，不改变登录请求行为。补充或更新测试并提交 PR，暂不合并。

观察 Superagent 是否创建 Ticket，在独立工作目录中修改函数和测试，并提交 PR。使用 `npm test` 验证结果。

## 第二轮：评审反馈

第一轮 PR 出来后，在该 PR 下发布评审评论：

> 请增加 NETWORK_TIMEOUT 提示“网络连接超时，请重试”，并补充或更新测试。其他提示保持不变，暂不合并。

观察评论是否进入原 Ticket，以及 Agent 是否在同一个 PR 中追加提交。验收完成后由人决定是否合并。

## 实验记录

保留 Issue 链接、Ticket ID、PR 链接、测试结果、评审评论和追加提交，作为协作闭环的证据。模型回复成功与真实工单执行成功需要分别验证。
